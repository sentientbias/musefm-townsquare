## NEW findings (not in bugs-2026-09-18-0635.md)

### P1 — OverflowError → HTTP 500 on ALL `<int:uid>` / `<int:pid>` routes with huge ints (systemic)
**Repro:**
```bash
curl -s -o /dev/null -w "%{http_code}\n" "http://127.0.0.1:8473/video/99999999999999999999999"   # 500
curl -s -o /dev/null -w "%{http_code}\n" "http://127.0.0.1:8473/gif/99999999999999999999999"     # 500
curl -s -o /dev/null -w "%{http_code}\n" "http://127.0.0.1:8473/photo-file/99999999999999999999999" # 500
curl -s -o /dev/null -w "%{http_code}\n" "http://127.0.0.1:8473/img/99999999999999999999999"     # 500
curl -s -o /dev/null -w "%{http_code}\n" "http://127.0.0.1:8473/audio/uploads/99999999999999999999999" # 500
curl -s -o /dev/null -w "%{http_code}\n" "http://127.0.0.1:8473/musefm/photos/99999999999999999999999" # 500
```
All return **500**. Small ints (`/video/999999`, `/img/999999`) return clean 404s — only >2^63 ints crash.
**Root cause (from server.log):**
```
File ".../videos.py", line 210, in get_video_upload
    r = db._one("SELECT * FROM video_uploads WHERE id=?", (uid,))
sqlite3.OverflowError: Python int too large to convert to SQLite INTEGER
```
Flask's `<int:>` converter accepts arbitrary-precision ints; the value goes straight into SQLite which caps at 64-bit. Same crash reachable via the signed API: `target_id=10**30` in a valid signed `react` / `vote` body → 500 (verified authenticated).
**Expected:** 404 (same as any other nonexistent id). **Fix hint:** clamp int params or catch `OverflowError` alongside `ValueError`/`TypeError` at the db layer.

### P1 — `/api/identity/register` with non-string `handle` → HTTP 500 (distinct crash site from the array-body class)
**Repro:**
```bash
curl -s -X POST http://127.0.0.1:8473/api/identity/register \
  -H "Content-Type: application/json" -d '{"handle":12345,"public_key":"AAA"}'  # 500
```
**Root cause (from server.log):**
```
File ".../app.py", line 980, in api_identity_register
File ".../db.py", line 894, in register_identity
    handle = (handle or "").strip()
AttributeError: 'int' object has no attribute 'strip'
```
Public, unauthenticated endpoint (10/hr rate limit). Valid JSON object, wrong field type — the morning run's report covers array bodies; this is a separate site in `db.register_identity` (also affects `avatar_url`/`bio` fields if given non-strings). **Expected:** 400 "bad handle".

## P2 nits / observations
- **`Server: Werkzeug/3.1.8 Python/3.12.3`** header on every response — exact version disclosure. Minor info leak; consider `server.set_header` override or a proxy.
- **`/vote` swallows all exceptions silently** (`except (ValueError, TypeError): pass`) then redirects home — invalid votes (bad value, unknown target) give the user a misleading success redirect instead of an error. Same pattern on web `/fb_react` failure path.
- **Trust-based handle impersonation on web routes** (`/vote`, `/fb_react`): anyone can vote/react as any handle (`handle=anything`, no cookie binding). Documented as intentional "trust-based (human browser)" design in the code — flagging only because it lets one browser farm votes as many handles (120/hr per IP shared bucket). If intended, fine; if not, bind to `ts_handle` cookie.
