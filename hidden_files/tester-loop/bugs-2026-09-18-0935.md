## P1 (NEW — surfaced in chat)

### 1. Huge-int OverflowError → HTTP 500 on all `<int:uid>`/`<int:pid>` routes + signed API (systemic)
- **Found by:** Adversarial QA; **verified by coordinator** (live repro + source + server.log: 12 OverflowError tracebacks).
- **Repro:** `curl "http://127.0.0.1:8473/video/99999999999999999999999"` → **500**; `/video/999999` → clean 404. Same crash on `/gif/`, `/photo-file/`, `/img/`, `/audio/uploads/`, `/musefm/photos/`. Also reachable via signed API: `target_id=10**30` in a valid signed `react`/`vote` body → 500.
- **Root cause:** Flask `<int:>` accepts arbitrary-precision ints; sqlite3 caps at 64-bit → `sqlite3.OverflowError: Python int too large to convert to SQLite INTEGER` (videos.py:210).
- **Expected:** 404 like any other nonexistent id. **Fix hint:** clamp int params or catch `OverflowError` at the db layer.

### 2. Non-string `handle` on `/api/identity/register` → HTTP 500 (public, unauthenticated)
- **Found by:** Adversarial QA; **verified by coordinator** via source (db.py:894 `handle = (handle or "").strip()` → `AttributeError` on int). Live repro blocked at re-check by the 10/hr rate limit (429 — limits work), but the agent hit the 500 pre-limit with `{"handle":12345,"public_key":"AAA"}`.
- Also affects `avatar_url`/`bio` fields with non-string JSON types. **Expected:** 400 "bad handle".

### 3. Concurrent requests cause intermittent HTTP 500s (shared sqlite connection, no lock)
- **Found by:** Human tester; **verified by coordinator** (source + server.log: 5 `sqlite3.InterfaceError: bad parameter or other API misuse` tracebacks).
- **Repro:** 30 parallel `GET /musefm/shorts` → 27×200 + 3×500. 10 parallel vote POSTs + 10 page GETs → 9/20 × 500. Sequential traffic: 0 failures. Race even 500s the 404 handler (`app.py:2223` → 404.html → same crash → **nonexistent URLs intermittently return 500 instead of 404**).
- **Root cause:** `db.py:519` `sqlite3.connect(path, check_same_thread=False)` (single shared connection) + `app.run(..., threaded=True)` (app.py:2236), no lock. 500 pages do NOT leak tracebacks (verified).
- **Impact:** real browsers open ~6 concurrent connections — ordinary human browsing trips this regularly. Most serious availability bug found to date.

### 4. Shop idempotency-key retry returns 402 after balance drops (idempotency contract broken)
- **Found by:** Agent tester; **proven by new failing test** `test_shop_idem_retry.py` (tests only, no source changed — per fix policy; 3 pass / 1 FAIL).
- **Repro:** register identity → 2 signed posts (35 Signal) → signed `shop_buy` rename_token with `idempotency_key="key-DDD"` → **200** charged 20 → retry same body (fresh signature, same key, balance now 15) → **402** "insufficient spendable Signal".
- **Root cause:** `shop.buy()` checks funds BEFORE the `UNIQUE(fm_id, ref_id)` idempotency insert; one-time items check `owns()` first (retry works), consumables with keys do not. No double-charge, but the client-visible contract is wrong (a completed, charged purchase reports as failed — exactly the retry-after-timeout case idempotency keys exist for).
- **Expected:** 200 `{"already_owned":true,"charged":0,...}`. **Fix hint:** check existing `(fm_id, ref_id)` row before the funds check.

### 5. Unsigned web forms can impersonate any registered identity's handle [design caveat]
- **Found by:** Human tester (P1); Adversarial QA noted the same sink on `/vote`/`/fb_react` (as P2, code-documented "trust-based").
- **Repro:** `POST /submit` (form-encoded, unsigned) with `handle=<another user's registered handle>` → 302 → post attributed to that handle, **indistinguishable from a genuine signed post**. Same in `/post/<pid>/comment`, `/vote`, `/api/episodes/<slug>/comments`.
- **Caveat:** code comments document these routes as intentionally "trust-based (human browser)". Kept at P1 because it directly undermines the musefm-v1 signed-identity trust model — anyone can farm votes/reacts and author posts as any handle — but the fix may be a deliberate design change (bind `ts_handle` cookie, or mark unverified posts), so this one is for Anthony to adjudicate.
