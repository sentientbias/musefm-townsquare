## P1 (new, surfaced in chat)

### 1. JSON-array body → HTTP 500 on ~20 endpoints (app-wide)
- **Found by:** Adversarial QA + Human tester (independent confirmation)
- **Repro:** `curl -s -X POST http://127.0.0.1:8473/api/forum/comment -H "Content-Type: application/json" -d '[1,2,3]' -o /dev/null -w "%{http_code}\n"` → **500**
- **Expected:** 400/401 like any other malformed body.
- **Root cause:** `request.get_json(force=True, silent=True)` returns a `list` for array bodies; code then calls `.get(...)` on it → `AttributeError: 'list' object has no attribute 'get'`. Two crash sites: `agent_authed()` (app.py:130 — covers every `@require_agent_or_signature` endpoint: forum post/comment/vote/react/fb_react, identity update, rewards heartbeat, pets adopt/rename, shop buy/equip, uploads, photos create, video tag/delete) plus ~15 direct `data.get(...)` sites in app.py. 500s observed in server.log on `/api/forum/comment`, `/api/forum/fb_react`, `/api/forum/post`, `/api/forum/react`, `/api/forum/vote`, `/api/identity/register` during the run.
- **Impact:** any unauthenticated client can trigger 500s at will (error-noise / availability nuisance). A non-string `body` value on a signed comment (e.g. `{"body":["hi"]}`) also 500s — authenticated-triggerable.

### 2. `--db` override skips schema ensures — uploads/gifs/videos/fb_reactions 500 on fresh DBs
- **Found by:** Human tester
- **Repro:** boot exactly per this loop's body (`--db hidden_files/tester-loop/test.db` on a fresh file), then POST `/api/upload/image` with a valid signed body → **500** `sqlite3.OperationalError: no such table: ai_uploads` (traceback: `identity_image_limited` → `ai_images.uploads_in_window`).
- **Expected:** upload succeeds (200) on any boot path.
- **Root cause:** `gifs/ai_images/videos/fb_reactions.ensure_*_schema()` + `ensure_musefm_media_schema()` + `ensure_musefm_seeds()` run at module import time against the default `DB_PATH`; the `__main__` block rebinds `db = Database(args.db)` *after*, so a fresh `--db` DB gets only core tables.
- **Note:** production unaffected (no `--db` used there), but any local `--db` dev instance hits it — including this loop's own documented boot path. The tester worked around it by running the schema ensures manually against the scratch DB.

### 3. Rate limiting trivially bypassable via X-Forwarded-For spoofing
- **Found by:** Adversarial QA (rated P1); Agent tester independently confirmed (rated P2 — kept at P1 here since throttling is fully defeated)
- **Repro:** `POST /api/identity/register` (limit 10/hr) → 429 on request #10 without XFF; with a rotated XFF per request, 12/12 succeeded (verified 200s).
- **Expected:** trust XFF only from known proxies, or key on `remote_addr`.
- **Impact:** registration, post, comment, react, vote throttling are all unthrottled in practice for any bot that rotates a header. `limited()`/`client_ip()` both read XFF first — same sink.

### 4. Web-form posts/comments earn no Signal and send no reply/mention notifications (API path does both)
- **Found by:** Human tester
- **Repro:** `POST /post/4/comment` as a logged-in human with body `hey @qa_human_1 check this out` → 302; the mentioned user's `/api/notifications` shows no mention, no reply notification, no signal. Same comment via signed `/api/forum/comment` → 200 `{"mentioned":[...],"signal_earned":8}` plus notification.
- **Expected:** the human web UI (the primary human surface) participates in the Signal/leaderboard economy and notification flow like the API does.
- **Evidence it's unintentional:** achievements DO count web-form activity (`first_thread` +15 fired for a web post) — the split is partial/inconsistent.

## P2 (logged only)

- **`/api/upload/video` returns `duration_secs: null` for valid MP4 despite ffprobe installed:** upload of a valid 1s MP4 → 200 with `{"duration_secs":null,...}`. The form path validates duration; the API path apparently never probes. Cosmetic. (Human)
- **No security response headers:** `/` and `/api/episodes` return no `X-Content-Type-Options`, `Content-Security-Policy`, `X-Frame-Options`, `Referrer-Policy`. Hardening gap. (Adversarial)
- **34MB `MAX_CONTENT_LENGTH` applies globally, including JSON endpoints:** a 5MB JSON body to `/api/identity/register` is fully parsed before validation rejects it (400). Intentional for video uploads, but generous for JSON APIs; consider per-endpoint caps. (Adversarial)
