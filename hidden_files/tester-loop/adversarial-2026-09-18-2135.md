## P1 — corroborated, not new
**SQLite lock contention → 500s on normal write paths under modest concurrency.**
`server.log` shows 10 `sqlite3.OperationalError: database is locked` tracebacks between 02:41:37–02:42:0x UTC on `/api/forum/vote`, `/api/forum/post`, `/api/rewards/heartbeat`, `/api/upload/gif`, `/api/upload/audio` while 2–3 testers hit the box concurrently. This matches the already-queued defect ("SQLite lock contention causing concurrent-write 500s") — confirming it reproduces easily with light parallel load, not just stress tests. Flask returns a bare 500 page on these; no data-loss evidence seen, but a user mid-post/upload gets an unexplained failure. Server stayed up throughout.

## P2s / nits
1. **Route collision: `GET /api/identity/register` → 404 `{"error":"unknown identity"}`** instead of 405. The `/api/identity/<fm_id>` route swallows action names ("register", "update") as fm_id lookups. Confusing for API consumers; route ordering/registration nit.
2. **`OPTIONS /api/forum/post` → 200 empty** (Flask auto-OPTIONS). Harmless; noting only because CORS-preflight surface wasn't otherwise advertised.
3. **`/api/shorts?page=999999999` → 200 echoing `"page":999999999`, items [].** Harmless; the SQL limit itself is clamped at 50 server-side (`videos.py`), so no unbounded query.
4. **Tester-loop procedural note:** the `identity_register` rate limit is 10/hr **per IP** — on this box the HTTP battery (7 register probes) plus other testers' concurrent traffic exhausted it, which blocked signed-flow HTTP testing for me mid-run. Not a product bug, but future runs should budget register calls or test from distinct IPs.

## Robustness: verified good
- **404s:** 14 nonsense paths (incl. `/%2e%2e/%2e%2e/etc/passwd`, `/admin`, `/moderator`, double-slash, bad-encoding) all 404, no stack leaks.
- **Wrong methods:** 25/29 returned 405; the 200s were login-page 302s followed by my client, and auto-HEAD on `/api/shorts`.
- **Malformed JSON:** empty/garbage/truncated/array/wrong-content-type bodies → clean 400 `{"error":"JSON body must be an object"}` on signed API routes; 401s where auth gates first. Zero 500s from my battery, zero traceback leaks in any HTTP response.
- **Missing params:** empty `{}` on 22 write endpoints → 400/401, never 500.
- **Unauthenticated hits on protected paths:** `/mod/flags`, `/mod/uploads`, `/mod/flags/1/resolve`, `/mod/uploads/image/1/approve`, `/settings`, `/submit`, `/photos/upload`, `/upload`, `/pet/adopt`, `/api/pets/adopt`, `/api/shop/buy`, `/api/challenges/settle` etc. — all properly 302 → `/login` or 401. (My tool followed redirects, initially showing 200s; verified via `-i` that these are genuine 302s. **No auth bypass.**)
- **Path traversal in file/id params:** `/audio/..%2f..%2fapp.py`, `/episode-video/..%2f..%2fapp.py`, `/img/..%2f..%2fapp.py`, `/static/..%2f..%2fapp.py` → all 400/404. The image upload pipeline uses `os.path.basename()` + magic-byte detection and stores as `img-<uid>.<detected-ext>` (code-reviewed `ai_images.create_image_upload`) — filename double-extensions/traversal are neutralized.
- **SQL injection probe:** `target_type="post' OR '1'='1"` → rejected by whitelist with ValueError. All id params are parameterized; non-int ids → 404.
- **Bursts:** 50× `/api/ping` → all 200 in 0.1s; 30× `/api/shorts` → all 200; 25× malformed `/vote` POSTs → all 401; 25× 404 burst → all 404. No degradation, no lock errors from read bursts.
- **Headers:** 20KB single header → 200; 100 headers → 431 (Werkzeug). No UA → 200.
- **Login garbage:** empty/garbage/truncated JSON to `/login`, `/signup` → 401, no 500s.
- **Share-link/id formats:** `/m/<weird>`, `/c/<slug>/post/<bad>`, `/video/abc`, `/img/-1`, `/gif/99999999`, `/episodes/<nonexistent>` → all clean 404s.
- **Query-param abuse:** `?limit=abc|-5|999999` on `/api/forum/posts` → clamped (max 100); `?page=abc|-1|1.5` on shorts → sane defaults. 3000-char query strings → 200, no blowup.
