## P1 — Concurrent requests cause intermittent HTTP 500s (threading bug)
- **Repro:** (a) 30 parallel `GET /musefm/shorts` → 27×200 + 3×500. (b) 10 parallel vote POSTs + 10 parallel page GETs → 9 of 20 returned 500. Single-threaded sequential traffic: 0 failures.
- **Evidence (server.log):** `sqlite3.InterfaceError: bad parameter or other API misuse` at `db.py:602` in `communities()` ← `app.py:255 inject_globals` ← template context update, for both `/musefm/shorts` and the `/does-not-exist` 404 handler (`app.py:2223` → `render_template("404.html")` → same crash → **nonexistent URLs return 500 instead of 404** when the race hits).
- **Root cause:** one shared `sqlite3.connect(path, check_same_thread=False)` in `db.py:519`, server runs `app.run(..., threaded=True)` (`app.py:2236`), no lock. Any two threads touching the DB at once can blow up.
- **Expected:** concurrent requests all succeed; 404s return 404.
- **Note:** real browsers open ~6 concurrent connections, so ordinary human browsing will trip this regularly. 500 pages themselves do NOT leak tracebacks (verified — no `Traceback` in any 500 body).

## P1 — Unsigned web forms can impersonate any registered identity's handle
- **Repro:** `POST /submit` (form-encoded, no signature) with `handle=battery5` (a *registered, signed* identity belonging to another test user) → 302 → post created at `/c/lobby/post/33`, API shows `"handle": "battery5"` — **indistinguishable from a genuine signed post** by that identity. Same trust hole in `POST /post/<pid>/comment`, `POST /vote`, and `POST /api/episodes/<slug>/comments` (all take `handle` from the request body, no verification).
- **Expected:** either web forms can't claim handles that belong to registered identities, or unverified posts are visually marked. Code comments say these routes are "trust-based (human browser)" — flagging because it directly undermines the musefm-v1 signed-identity trust model the rest of the app is built on.
- **What I got:** 302 + `Set-Cookie: ts_handle=...`, post attributed to the victim handle, no signal awarded (no identity attached).

## Verified OK (not bugs)
- **Stored XSS:** `<script>`, `<img onerror>`, `javascript:` hrefs in post titles/bodies, comments, and profile bios all render Jinja-escaped on thread/profile/episode pages; quotes escaped as `&#34;` inside `og:title` attributes. No raw script anywhere in HTML.
- **Upload binding:** `/api/upload/image|gif|audio|video` enforce magic bytes (fake PNG/GIF/MP4 rejected), `file_sha256` must match bytes (mismatch → 401), size caps enforced, and `/api/photos/create` returns **403** when publishing another identity's upload ("only the uploading identity may publish its image").
- **musefm-v1 auth:** unsigned → 401, wrong action → 401, tampered fields → 401 "signature does not verify", replayed nonce → 401 "replay: nonce already used".
- **Registration validation:** duplicate handle → 400, bad handle chars → 400, bad Ed25519 pubkey → 400, non-http(s) avatar_url → 400. Rate limits enforced per IP (register 10/hr, post 5/hr observed working).
- **Votes/reactions:** double-vote toggles off (score 1→0), flip to -1 works; `value=0`/`5` → 400 "value must be 1 or -1"; vote on missing target → 400 "unknown target". Emoji whitelist enforced (`💩` → 400). Self-reaction earns **no** Signal; only others' reactions award +2 to the author (verified in rewards history). FB reactions: like → added, love → switched, love again → removed. Comment votes/reactions work.
- **Validation:** empty title → 400, empty comment → 400, unknown community → 400, unknown parent comment → 400, bad image_url (`javascript:`, `data:`, `file://`, `//evil.com`) → 400 "bad image url". Web form variants return proper 400/404 with plain-text errors.
- **Pages:** `/`, `/musefm`, `/episodes`, `/musefm/shorts`, `/shorts`, `/watch/<uid>`, `/musefm/photos`, `/photos/upload`, `/network`, `/signal`, `/pet`, `/shop`, `/api/docs`, `/submit` all 200; unknown community/thread/profile/episode/watch → 404; wrong method → 405/404 as appropriate.
