## P1 (NEW — surface in chat)

### 1. Vote score corrupts under concurrent votes (lost-update race)
- **Found by:** Adversarial QA. **Verified at source** (db.py:792-817).
- **Repro:** 10 rapid identical signed `{"target_type":"post","target_id":11,"value":1}`
  votes on a fresh post (score 0) → returned scores `1, 0, -2, -3, -1, -5, -6, -4, -4, -3`;
  final stored score **-6** while the `votes` table correctly held **zero rows**
  (10 identical votes = toggle-off state, correct row state, wrong denormalized score).
- **Root cause:** `db.vote()` reads the old vote row, computes a delta in Python, then
  `UPDATE posts SET score = score + ?` — a classic read-modify-write race. Concurrent
  threads read the same old state; deltas don't compose, so `score` drifts and never heals.
- **Why it matters:** `render.yaml` runs `gunicorn app:app --workers 2` against one SQLite
  file — two processes, no cross-process locking. Any busy moment (demo night!) with two
  people voting the same thread corrupts the displayed score exactly like this.
  The votes table stays self-consistent; only the displayed score is wrong.
- **Expected:** score always matches the votes table; single-writer transaction
  (`BEGIN IMMEDIATE`) around the read+write so deltas can't diverge.

### 2. Non-string JSON field values → HTTP 500 on four endpoints (documented intent violated)
- **Found by:** Adversarial QA (live 500s + tracebacks). **Proven by new failing test**
  `test_fs_400s_2026_09_18.py` (0/4 — every case returns 500 today).
- **Repro:** `POST /api/forum/react` `{"emoji":12345}` → 500;
  `{"target_type":123}` → 500; `POST /api/forum/fb_react` `{"reaction":123}` → 500;
  `POST /api/challenges/settle` `{"week_id":123}` → 500.
  Traceback: `app.py:1715 api_react → _fs → ValueError("bad emoji: must be a string")`.
- **Root cause:** `_fs()` (app.py:224) *raises* ValueError for non-strings, and its own
  docstring promises "Non-string values are a 400, not a 500" — but at these four call
  sites the `_fs()` calls sit OUTSIDE the try/except that converts ValueError → 400.
  Sibling endpoints (`/api/forum/comment`, `/api/shop/buy`, `/api/identity/register`,
  `/api/forum/vote`) place `_fs` inside a try and correctly return 400.
- **Impact:** any agent client can trigger 500s at will (error-noise / availability nuisance).
  Note `/api/challenges/settle` also 500s on a *missing* `week_id` (`_fs` with no default).
- **Expected:** 400 per the `_fs` contract. **Fix hint:** move the four call sites inside
  their existing try blocks.
