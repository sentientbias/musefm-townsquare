## P1

### 1. Open redirect on login `next` — `//evil.com` passes the guard
- Repro: `GET /login?next=%2F%2Fevil.com`, log in with valid creds.
- Code: app.py `login()`: `if not nxt.startswith("/"): nxt = "/"  # no open redirects`.
  `"//evil.com".startswith("/")` is True, so `redirect("//evil.com")` is issued.
  Browsers treat `Location: //evil.com` as protocol-relative → victim lands on
  evil.com right after a legitimate login (phishing page can say "session expired,
  log in again"). Fix: require `nxt.startswith("/") and not nxt.startswith("//")`.
- Expected: off-site `next` values collapse to `/`.

### 2. `POST /submit` → 500 `sqlite3.OperationalError: database is locked`
- Repro: `POST /submit` (valid session, normal title/body) while the other two
  testers were hammering writes. Traceback in server.log 20:39:28 UTC:
  `db.py:712 create_post → _exec → sqlite3.OperationalError: database is locked`.
  `PRAGMA busy_timeout = 5000` was exceeded — one shared sqlite connection
  (`check_same_thread=False`) plus concurrent writers. A normal human posting
  during a busy window gets a 500 and (likely) retries → duplicate posts.
  Consider WAL mode + retry-on-locked, or serializing writes.
- Expected: post succeeds or gets a clean 429/503, never a 500.

## P2

### 3. CSRF token checked inconsistently
Checked on: `/post/<pid>/comment`, `/vote`, `/flag`, `/episodes/<slug>/comment`,
`/settings/link`, `/settings/unlink`, `/shorts/<uid>/comment`.
NOT checked on: `/submit` (create thread), `/fb_react` (web), `/photos/upload`.
Verified by form-POSTing without any token: comment → 403 "bad form token",
vote → 403, but /submit and /fb_react and photo upload proceed. Real-world
exploitability is LOW (session cookie is `SameSite=Lax`, so cross-site POSTs
don't carry it), but the split is an accident waiting to happen — make it uniform.
Token is delivered via `<meta name="csrf-token">` for JS fetch; plain no-JS form
POSTs have no hidden field, so no-JS comment/vote submissions 403 (minor UX).

### 4. No security headers
`GET /` returns zero `X-*` / CSP headers: no `X-Content-Type-Options`,
no `X-Frame-Options`, no `Content-Security-Policy`. Output escaping is solid
(see below), so this is hardening, not an active hole.

### 5. `/api/forum/posts?search=` silently ignored
API reads `?q=` (app.py:1395); `?search=` returns unfiltered results. Web UI
uses `q=` so no user impact — undocumented-param nit.
